    Cloud-Config and ros config Keys

    The same keys are used in the cloud-config file given at installation or first boot and with ros config set <key> <value> / ros config merge later on, see Configuration. The defaults come from the os-config.tpl.yml template of the BurmillaOS version you run. sudo ros config export --full prints the complete effective configuration of your installation including all defaults, which is the quickest way to see the current value and the exact spelling of a key.

    Top-Level Keys

    KeyTypeDescription
    hostnamestringHostname of the system
    ssh_authorized_keyslist of stringsPublic keys added to the rancher user, see SSH keys
    write_fileslist of filesFiles to write on boot (path, content, permissions, owner, encoding), see Writing files
    runcmdlist of commandsCommands run in the console on boot, before Docker starts, see Running commands
    bootcmdlist of commandsCommands run early in the boot process, before the console starts
    mountslist of [device, path, fstype, options]Additional mounts
    ranchermapBurmillaOS specific settings, see below

    Other cloud-init directives such as users are not supported, see Users.

    rancher Keys

    KeyTypeDescription
    rancher.consolestringConsole to use, see Switching consoles
    rancher.dockermapUser Docker settings, see below
    rancher.system_dockermapSystem Docker settings, same keys as rancher.docker
    rancher.bootstrap_dockermapSettings of the Docker used during the bootstrap phase of the boot, same keys as rancher.docker
    rancher.environmentmapEnvironment variables passed to system services, e.g. HTTP_PROXY, see Environment and Proxy settings
    rancher.servicesmapCustom system services and overrides for built-in services, in Docker Compose v1 format
    rancher.services_includemap of booleansOptional system services from the service repository to enable, e.g. open-vm-tools: true
    rancher.bootstrapmapServices run during the bootstrap phase (before the state partition is mounted)
    rancher.cloud_init_servicesmapServices run while cloud-init fetches the configuration
    rancher.cloud_init.datasourceslist of stringsWhere to fetch user data and metadata from, e.g. configdrive:/media/config-2, ec2, gce, digitalocean, vmware, azure, proxmox, url:<URL>, file:<path>, see Cloud init
    rancher.networkmapInterfaces, DNS, proxy and other networking settings
    rancher.ssh.keysmapHost keys of the sshd in the console (generated on first boot, exported with ros config export --private)
    rancher.ssh.daemonbooleanRun sshd in the console (default true)
    rancher.ssh.portintegerPort sshd listens on
    rancher.ssh.listen_addressstringAddress sshd listens on
    rancher.statemapState partition settings: dev, fstype, directory, wait, required, autoformat, mdadm_scan, lvm_scan, cryptsetup, rngd, script, oem_dev, oem_fstype, boot_dev, boot_fstype
    rancher.upgrade.urlstringURL of the releases.yml used by ros os list / ros os upgrade, see Upgrading
    rancher.upgrade.imagestringImage used for upgrades (default burmilla/os)
    rancher.repositoriesmapService repositories (core is the BurmillaOS os-services repository), see Air gap configuration
    rancher.registry_authsmapCredentials for private registries used by System Docker
    rancher.moduleslist of stringsExtra kernel modules to load on boot, see Loading kernel modules
    rancher.sysctlmapKernel parameters, see Sysctl settings
    rancher.resize_devicestringDevice whose first partition is grown to the full disk on boot, see Resizing a device partition
    rancher.disablelist of stringsConsole features to disable: password (password login) and autologin (automatic login on the local ttys), see Disabling access
    rancher.restart_serviceslist of stringsSystem services to restart after cloud-init has applied the configuration
    rancher.hypervisor_servicebooleanAutomatically enable the open-vm-tools or hyperv-vm-tools service when the matching hypervisor is detected (default true)
    rancher.shutdown_timeoutintegerSeconds to wait for containers to stop on shutdown
    rancher.http_load_retriesintegerRetries when fetching the cloud-config or service definitions over HTTP
    rancher.preload_waitbooleanWait for image preloading to finish before starting Docker
    rancher.force_console_rebuildbooleanRecreate the (persistent) console container on boot
    rancher.debugbooleanEnable debug logging of ros
    rancher.logbooleanStream the output of system services to the console log while they start, see Logging
    rancher.recoverybooleanBoot the recovery console
    rancher.defaultsmapDefaults for hostname, docker, network and system_docker_logs, meant for OEM configuration

    Keys such as rancher.rm_usr and rancher.no_sharedroot exist for compatibility with RancherOS and should not be changed.

    rancher.docker Keys

    These keys configure the user Docker engine. The same keys exist under rancher.system_docker and rancher.bootstrap_docker. See Docker configuration for examples.

    KeyTypeDescription
    rancher.docker.enginestringDocker engine to run, e.g. docker-29.2.1 or latest, see Switching Docker versions
    rancher.docker.extra_argslist of stringsAdditional dockerd command line arguments, e.g. ["--default-ulimit", "nofile=65536:65536"]
    rancher.docker.environmentlist of stringsEnvironment variables for the Docker daemon, e.g. ["HTTP_PROXY=http://proxy:3128"]
    rancher.docker.tlsbooleanEnable TLS on the Docker API, see Setting up Docker TLS
    rancher.docker.tls_argslist of stringsdockerd arguments used when tls is enabled
    rancher.docker.server_cert, server_key, ca_cert, ca_keystringTLS certificates and keys (set by ros tls generate)
    rancher.docker.hostlist of stringsSockets / addresses the daemon listens on (-H)
    rancher.docker.groupstringGroup owning the Docker socket (default docker)
    rancher.docker.storage_driverstringStorage driver, e.g. overlay2
    rancher.docker.data_rootstringData directory of the daemon (default /var/lib/docker)
    rancher.docker.exec_rootstringExec root directory of the daemon
    rancher.docker.pid_filestringPID file of the daemon
    rancher.docker.config_filestringdaemon.json to load
    rancher.docker.log_driverstringDefault container log driver
    rancher.docker.log_optsmapDefault container log options, e.g. max-size: 25m
    rancher.docker.insecure_registrylist of stringsRegistries to allow over plain HTTP
    rancher.docker.registry_mirrorstringRegistry mirror URL
    rancher.docker.bridge, bipstringBridge name and IP range of the default bridge network
    rancher.docker.live_restorebooleanKeep containers running while the daemon restarts
    rancher.docker.userland_proxybooleanUse the userland proxy for port forwarding
    rancher.docker.debugbooleanDaemon debug logging

    Boolean and list values are given to ros config set in YAML syntax, e.g. sudo ros config set rancher.docker.extra_args "['--default-ulimit','nofile=65536:65536']". A reboot (or sudo system-docker restart docker for rancher.docker keys) is needed before changed values are applied.
